## 让 Live2D 看板娘可拖动

### 已确认的三个关键约束（都来自读源码，非推测）

1. **widget 独占容器的 `transform`**。默认 slide 模式下 `Go()` 把 `container.style.transform` 写成 `translateY(0)`/`translateY(130%)` 做显隐动画（`dist/index.js:11980`），并带 `transition: transform 1500ms`。所以**绝不能用 transform 做拖动**——每次 sleep/切换模型/销毁都会把拖动位置覆盖掉，且 1500ms 过渡会让拖动跟手性极差。
   → **改用 `left`/`bottom` 定位**，与 transform 完全解耦。

2. **容器监听冒泡的 `transitionend`**。`A()` 在容器上挂一次性 `transitionend` 监听（`dist/index.js:12080`），`switchModel` 和 `destroy` 都 `await` 它。子元素（气泡、菜单）的过渡结束也会冒泡触发它。
   → 拖动过程中**不能给容器或其子元素引入新的 transition**，否则会让切换模型/销毁提前放行，退出动画被打断。拖动时把过渡设为 `none`。

3. **容器没有 id/class，且三个部件是 body 下的兄弟节点**：
   - `dist/index.js:12031` 容器 `f`（含 canvas）→ `body`
   - `dist/index.js:12033` 状态条 `m.el` → `body`，独立定位在 `bottom: size/2; left: 0`
   - `dist/index.js:12119` 菜单 `g.el` → **追加到 `f` 内部**

   即：**菜单会跟着容器走，状态条不会**。模型休眠时那条「正在休息」会留在原角落。需要一并同步。

### 实现方案

**1. `src/types/pioConfig.ts`** — 加配置类型：
```ts
draggable?: {
    enable?: boolean;      // 默认 true
    longPressMs?: number;  // 触发拖动的长按时长，默认 150
    savePosition?: boolean;// 是否记忆位置，默认 true
};
```

**2. `src/config/pioConfig.ts`** — 加对应配置块（默认开启、记忆位置）。

**3. `src/components/features/Live2DWidget.astro`** — 核心改动，在 `createWidget` 之后接线：

- **拿到容器**：`createWidget` 返回的实例上 `widget.l2d.getCanvas()` 是公开方法（`dist/index.js:11648`，`return this.canvas`），其 `parentElement` 即容器。比按 `body > div[style*=fixed]` 之类猜测性选择器稳，也不会误伤页面上其它 fixed 元素（仓库里有 10+ 处 fixed 样式）。

- **定位解耦**：拖动开始时把容器的初始 `left`/`right`/`bottom` 换算成显式的 `left`/`top` 像素值（读 `getBoundingClientRect()`），并清掉 `right`/`bottom`，之后只用 `left`/`top`。同时临时 `transition: none`（规避约束 2）。

- **长按拖动**：`pointerdown` 起计时器，超过 `longPressMs` 才进入拖动态；未超时就抬起则**不拦截**，交给模型自带的 click 换动作。拖动中用 `setPointerCapture`，`pointerup`/`pointercancel` 收尾。这沿用了仓库既有的指针拖动写法（`src/plugins/plantuml-render-script.js:197`、`diagram-panzoom-script.js:103`：closure 状态 + `setPointerCapture?.()` + up/cancel 清理 + cursor 反馈）。

- **边界钳制**：拖动和窗口 resize 时都把位置限制在视口内，避免窗口变小后模型跑到屏幕外找不回来。

- **状态条同步**：拖动结束后按容器的最终位置同步状态条的 `left`/`bottom`（用容器高度推 `bottom: size/2`），让休眠条跟着模型走。

- **持久化**：`localStorage` 存 `{left, top}`（键名沿用仓库惯例的小写无前缀风格，如 `live2dPosition`；写入用 try/catch 静默失败，参照 `src/utils/failed-covers.ts:3`）。初始化时读回并按当前视口钳制。**切页时 swup 不重建容器**（已在上一轮验证），位置天然保留；resize 时重新钳制。

- **拖动按钮**：给菜单加一个「重置位置」项（`action: "resetPosition"`），方便拖丢后一键复原——`menuActions` 是既有的字符串→函数映射表，加一项即可。

- **清理**：`destroy` 前先移除我注册在 `document`/容器上的拖动监听（widget 的 `destroy()` 不知道它们，只清自己的；`dist/index.js:12112`）。

### 会碰到的取舍（明确告知）

- **长按会吃掉「按住不放」的既有交互**：模型本身是「鼠标移动即视线跟随」，拖动期间视线仍会跟着鼠标摆动（core 的 `mousemove` 挂在 `document` 上），这是既有行为，我不改。
- **拖动进行中的 1500ms 过渡被临时置为 none**，松手后恢复，所以拖动过程中显隐动画会瞬时完成——但拖动中本来也不会触发显隐。
- **移动端**：当前配置 `hideOnMobile: true`，移动端不显示，所以拖动只需要处理鼠标/笔（`pointerType` 判断保留，逻辑上仍兼容触屏，只是当前配置下用不到）。

### 验证方式

`pnpm type-check` + `pnpm check`（注意：`booknav.astro`/`sponsor.astro` 那 2 个报错是既有问题，与本次无关，我会对比基线确认没有新增）；`pnpm build`；然后用浏览器实测——真实拖动、刷新后位置是否保留、拖动后休眠条是否跟随、切页后位置是否还在、以及**确认拖动没有让 `switchModel`/`destroy` 的过渡逻辑提前放行**。
